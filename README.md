# shreyasprasad.dev

Personal site and home for small browser-only apps. Astro 7 in fully static mode, plain CSS, and
Vite-built apps, served by Cloudflare Workers Static Assets. A small Worker serves each app at its own
subdomain (`anagrams.shreyasprasad.dev`). The only server-side state is Solfa Echo Live's classroom
rooms, one Durable Object each, deleted when the game ends.

## Development

Needs Node 22.23.4+ (`nvm use` reads `.nvmrc`) and pnpm (`corepack enable` picks up the pinned version).

```sh
pnpm install
pnpm dev        # site at http://localhost:4321 (apps aren't served here; see below)
pnpm build      # astro check, astro build, build apps into dist/apps/, check internal links
pnpm preview    # build, then serve dist/ with Wrangler exactly as Cloudflare will
```

Under `pnpm preview`, apps are at `http://<slug>.localhost:8787/` as well as `/apps/<slug>/`.

## Layout

```
src/content/projects/   one Markdown write-up per project
src/content/notes/      one Markdown post per note (draft: true renders in dev only)
src/content/apps/       one metadata file per app; drives /apps and the homepage teaser
src/pages/              routes: /, /projects/[slug], /notes, /notes/[slug], /apps, /rss.xml, 404
apps/<slug>/            standalone Vite apps, each built to /apps/<slug>/ and served at <slug>.shreyasprasad.dev
worker/index.ts         maps <slug>.shreyasprasad.dev to /apps/<slug>/, redirects old /apps/<slug>/ URLs there,
                        and routes an app's /api/* to its server code in apps/<slug>/worker/
public/                 copied as-is: _headers, _redirects, diagrams, favicon, og.png
scripts/                build-apps.mjs and check-links.mjs, run by `pnpm build`
```

## Adding an app

1. Scaffold `apps/<slug>/` (`pnpm create vite apps/<slug>`) and set `base: './'` in its `vite.config.ts`,
   so it works at the subdomain root and under `/apps/<slug>/` on preview URLs. Use hash routing or none:
   there's no SPA fallback. Link back to the site with absolute `https://shreyasprasad.dev/...` URLs,
   since root paths like `/apps/` resolve against the app's own subdomain.
2. Add `src/content/apps/<slug>.md` with `title`, `description`, `date`, `tags` and `tier: 2`.
3. Develop with `pnpm --filter <slug> dev`. `pnpm build` builds it and fails if the metadata file is missing.

No DNS or Cloudflare change is needed: the wildcard route picks up the new subdomain on the next deploy.

A single-file experiment can instead go in `public/apps/<slug>/index.html` with `tier: 3`.
Per-app response headers (CSP, COOP/COEP for `SharedArrayBuffer`) go in `public/_headers`.

## Anagrams

`apps/anagrams/` is a daily word game, ported to Preact. Its word lists
are generated by `apps/anagrams/data-pipeline/`; after changing the pipeline's outputs, run
`node apps/anagrams/data-pipeline/build_app_data.mjs` to regenerate `apps/anagrams/public/`.

## Solfa Echo

`apps/solfa-echo/` is an ear-training game: it plays a growing pattern of solfège notes and you tap it
back on a ladder or piano. The rules live in a pure state machine (`src/games/says/SaysGame.ts`) with
the music model, audio and input surfaces in `src/core/` and `src/ui/`, so later games can share them.
`pnpm --filter solfa-echo test` runs its unit tests. The samples in `public/samples/` are one mp3 per
note from the midi-js-soundfonts project; `public/samples/CREDITS.md` has their sources and licenses.

**Live** (`#/host`, `#/join/<code>`) is the classroom version: the teacher's screen hosts a room with a
join code, students join from their own devices with nicknames, and everyone answers the same pattern
with three lives each and a live leaderboard. The pieces:

```
apps/solfa-echo/src/shared/   rules, protocol and nickname checks, imported by both the app and the Worker
apps/solfa-echo/src/live/     the board (host/) and student (player/) screens, and the WebSocket client
apps/solfa-echo/worker/       the API (POST /api/rooms, GET /api/rooms/:code/ws) and the Room Durable Object;
                              room-core.ts holds the game rules, room.ts the sockets, storage and alarms
```

The Room uses the WebSocket hibernation API and alarms (no timers), so it sleeps unbilled between
messages and a classroom game stays inside the Workers Free plan. Rooms are deleted when the teacher
closes them or after two idle hours. To develop Live, run the Worker and the app side by side:

```sh
pnpm exec wrangler dev              # repo root: the Worker and Durable Object on :8787 (serves the last build)
pnpm --filter solfa-echo dev        # the app; Vite proxies /api, including WebSockets, to :8787
node apps/solfa-echo/scripts/live-load.mjs http://localhost:8787/apps/solfa-echo/ 40 3   # 40 bot students
```

## Deployment

Cloudflare Workers Builds deploys from the Git repo: pushes to `main` go to production, and other
branches get preview URLs. Build command `pnpm build`, deploy command `npx wrangler deploy`. Node comes
from `.nvmrc` and pnpm from `packageManager` in `package.json`. The Worker name in `wrangler.jsonc`
matches the one the custom domain is attached to.

App subdomains need two one-time settings in the Cloudflare dashboard, kept out of `wrangler.jsonc`
because a route there makes `wrangler dev` rewrite every hostname to `shreyasprasad.dev`:

- DNS: a proxied wildcard record, `AAAA` `*` → `100::`. Cloudflare's free certificate covers one level
  of subdomain, so `<slug>.shreyasprasad.dev` works over HTTPS and `a.b.shreyasprasad.dev` doesn't.
- Worker route: Workers & Pages → `shreyasprasad-dev` → Settings → Domains & Routes → Add route,
  `*.shreyasprasad.dev/*`. `wrangler deploy` leaves dashboard routes alone while the config lists none.

Every request now runs the Worker (`run_worker_first`), so it counts toward the Workers request quota
(100,000 a day on the free plan) instead of being a free static-asset request.
